# Projection Semantics and Publication Layers

## Why this distinction matters

A projected semantic graph can remain completely valid while supporting many different outputs. Even orthodox astrology can be written in multiple voices, depths, focuses, and organizational structures. Context adds another independent dimension: manager–employee, parent–child, partners, collaborators, handlers and dogs, or technical auditors may need different claims emphasized even when the underlying projected graph is unchanged.

The architecture should therefore avoid treating one report writer as the projection layer's natural endpoint.

## Emerging layer model

```text
canonical source graph
→ projection profile / target ontology
→ projected term registry
→ intermediate semantic reasoning
→ report specification and context policy
→ renderer
→ style / voice / audience pack
→ published artifact
```

### Target ontology

Defines the kinds of projected objects, modes, domains, interfaces, and relationships that can exist.

### Projected term registry

Defines the vocabulary used by that ontology: stable meanings, core operators, facets, labels, and grammatical composition guidance.

The registry does not decide which claims matter most in one report.

### Intermediate semantic reasoning

May identify:

- architectural centers of gravity;
- repeated motifs;
- tension circuits;
- facilitation bridges;
- multi-node functional complexes;
- inferred processing sequences;
- evidence-weighted claims.

### Report specification and context policy

Determines what should be emphasized for a particular use. Context can alter semantic relevance, not merely wording. A manager–employee relationship read and a parent–child read may reason differently about the same relational structure.

### Renderer

Turns structured semantic content into sentences, paragraphs, sections, or other presentational units.

### Style, voice, and audience pack

Controls tone, vocabulary level, metaphor density, sentence rhythm, warmth, formality, playfulness, and accessibility. Style is not the same as context: two manager–employee reports may share semantic focus while using very different voices.

## Semantic-field distinctions

The projection graph currently exposes several related but non-equivalent concepts:

- **operators** describe what a subsystem does;
- **modes** describe how it tends to perform that function;
- **domains** describe where or under what structural conditions the function is organized;
- **theme tags** support retrieval, grouping, and semantic association;
- **context references** identify the projection context under which the mapping was valid;
- **salience and relevance scores** help rank structural importance without defining meaning;
- **provenance and mapping-rule refs** explain why the projected item exists;
- **projected term refs** resolve the target-domain vocabulary into the registry.

Consumers should not treat these fields as interchangeable keyword collections.

## Lessons from registry-grounded cognitive and Woofmapped reads

The registry-grounded reports preserved the same broad architectures found before registries while improving:

- human readability;
- semantic confidence;
- vocabulary consistency;
- subsystem coverage;
- cross-referencing;
- practical deductions;
- multi-node system synthesis.

The registry clarified rather than replaced the projection. Stable conclusions across the pre-registry and registry-grounded reports suggest the original graph already contained meaningful structure; the registry reduced the need to reverse-engineer compound identifiers and let the narrator spend more effort on relationships and larger architectural patterns.

The Woofmapped comparison made the result especially visible. Pack identity, cue interpretation, rule structure, adventure, and primal trust could be read as a Doghouse 8 Trust Core. Other useful distinctions included:

- trust as platform rather than prize;
- training the meaning of a cue, not only its visible behavior;
- a safe place not guaranteeing a regulated body;
- successful role performance not implying low internal cost;
- humor becoming mnemonic rather than load-bearing.

These profiles are beginning to function as domain-specific semantic languages: they contain definitions, operators, facets, composition rules, stable meanings, and enough discourse support to reason inside the projected domain.

## Consumer-facing reporting rule

Normal projected chart reads should present meaning directly. They should not routinely say:

- “the registry defines...”;
- “the graph shows...”;
- “several dataset elements support...”;
- “this object operates through mode X in domain Y.”

Those formulations belong in audit, research, or technical modes. Consumer prose should preserve the semantics while hiding the machinery.
