# Semantic projection

Semantic projection preserves a source system's structural roles while expressing them in a target ontology.

```text
canonical source primitives and relations
        + target profile
        + application context
        -> projected primitives and relations
```

It is not prose translation. If a source operator maps to an execution mechanism and another maps to a valuation mechanism, their source relationship must be reasoned about between those projected functions. Translating a completed orthodox interpretation afterward would import assumptions that may not exist in the target domain.

Projection also cannot begin from raw coordinates alone. A trustworthy shared substrate must retain source identity, object roles, relationship topology, derivation lineage, structural strength, registries, and provenance.

The resulting order is:

1. Calculate source-domain facts upstream.
2. Compile a canonical graph and conservative structural evidence.
3. Project primitives and relationships through a versioned profile and context.
4. Reason and synthesize within the projected ontology downstream.
5. Plan and publish application-specific outputs.

Orthodox astrology is therefore an explicit profile, not invisible universal meaning. Cognitive Architecture and Woofmapped Astrology use the same compiler to demonstrate that source structure can support materially different target ontologies without changing the engine.

Core invariants are:

- preserve source facts and provenance;
- never mutate inputs;
- make mappings and exclusions auditable;
- keep profile vocabulary versioned;
- distinguish structural strength from profile/context relevance;
- preserve contradictions and limitations rather than smoothing them away;
- delay application claims and presentation until downstream context requires them.
